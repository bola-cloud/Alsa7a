# توثيق التحديثات الجديدة - تطبيق الساحة

هذا الملف يحتوي على توثيق للميزات الجديدة: الرسائل الصوتية في الشات، نظام الاستوري، والتحديث الخاص بإجبارية التوثيق لإنشاء الخدمات.

---

## 1. الرسائل الصوتية في الشات (Voice Notes)
تمت إضافة دعم لإرسال رسائل صوتية في المحادثات. لم يعد حقل النص `body` إجبارياً في حال وجود رسالة صوتية.

**الطريقة:** `POST`
**المسار:** `/api/v1/chat/{conversation_id}/messages`

**البارامترات الإضافية:**
- `voice_note` (اختياري - نوع `file`): ملف صوتي (أقصى مساحة 20 ميجابايت). الامتدادات المسموحة: `mp3, m4a, wav, aac, ogg, mpga`.
- `body` (اختياري في حال وجود صوت): إذا تم إرسال رسالة صوتية مع ترك `body` فارغ، سيقوم السيرفر تلقائياً بحفظه كـ `"Voice Note"`.

**في الـ Response عند جلب الرسائل:**
ستلاحظ وجود حقل `file_url` بداخل الأوبجكت الخاص بالرسالة، وهو يحتوي على الرابط الكامل للملف الصوتي جاهزاً للتشغيل. حقل `meta` القديم سيظل كما هو دون تغيير أو تدخل من الباك إند بناءً على طلبكم.

```json
{
    "id": 1500,
    "conversation_id": 12,
    "sender_id": 5,
    "body": "Voice Note",
    "meta": null,
    "file_url": "https://alsaha.tech/storage/chat/voices/filename.mp3",
    "created_at": "2026-06-30T10:00:00.000000Z"
}
```

## 2. نظام الاستوري (Stories System)
تم تطبيق نظام استوريز (نصوص، صور، فيديو) يختفي تلقائياً بعد 24 ساعة.

**أ. جلب الاستوريز:**
- **الطريقة:** `GET`
- **المسار:** `/api/v1/stories`
- **الوصف:** يعيد الاستوريز الخاصة بالمستخدم نفسه + المستخدمين الذين يتابعهم، مجمعة (Grouped) حسب المستخدمين.
- **مثال للرد:**
```json
{
    "status": true,
    "data": [
        {
            "user": {
                "id": 1,
                "name": "أحمد",
                "profile_photo_path": "..."
            },
            "stories": [
                {
                    "id": 10,
                    "type": "video",
                    "content": null,
                    "media_url": "https://alsaha.tech/storage/stories/videos/compressed.mp4",
                    "expires_at": "2026-07-01T15:00:00.000000Z",
                    "created_at": "2026-06-30T15:00:00.000000Z"
                }
            ]
        }
    ],
    "message": "Stories retrieved successfully"
}
```

**ب. إنشاء استوري جديدة:**
- **الطريقة:** `POST`
- **المسار:** `/api/v1/stories`
- **البارامترات:**
  - `type` (إجباري): نوع الاستوري (`text` أو `image` أو `video`).
  - `content` (اختياري): نص الاستوري (إجباري في حال كان النوع text).
  - `media` (اختياري): ملف الصورة (حتى 10MB) أو الفيديو (حتى 30MB). إجباري في حال كان النوع `image` أو `video`. *(يتم ضغط الفيديو تلقائياً في السيرفر)*.

**ج. تسجيل مشاهدة الاستوري:**
- **الطريقة:** `POST`
- **المسار:** `/api/v1/stories/{id}/seen`

**د. جلب المشاهدات (لصاحب الاستوري فقط):**
- **الطريقة:** `GET`
- **المسار:** `/api/v1/stories/{id}/views`

**هـ. حذف الاستوري قبل مرور 24 ساعة:**
- **الطريقة:** `DELETE`
- **المسار:** `/api/v1/stories/{id}`

**و. تعديل استوري:**
- **الطريقة:** `POST`
- **المسار:** `/api/v1/stories/{id}`
- **البارامترات:**
  - `type` (اختياري): نوع الاستوري الجديد (`text` أو `image` أو `video`).
  - `content` (اختياري): نص الاستوري الجديد.
  - `media` (اختياري): ملف الصورة أو الفيديو الجديد في حال التغيير.

## 3. إعدادات المنصة: التوثيق الإجباري لإنشاء خدمة
تم إضافة إعداد جديد يتحكم في إمكانية إنشاء خدمة للمستخدمين بناءً على حالة توثيقهم. هذا الإعداد يمكن تشغيله أو إيقافه من لوحة تحكم الإدارة.

**كيف يؤثر على الموبايل؟**
في الـ API الخاص بجلب الإعدادات `GET /api/v1/settings` ستجد متغيراً جديداً:
- `mandatory_service_verification` (boolean): إذا كان `true`، فهذا يعني أن التطبيق لا يُفترض أن يسمح للمستخدم بإنشاء خدمة إلا إذا كان موثقاً.

**ماذا سيحدث في الباك إند؟**
عند محاولة استدعاء مسار `POST /api/v1/services` (إنشاء خدمة)، إذا كان هذا الإعداد مفعلاً وكان حساب المستخدم غير موثق (`verification_status !== 'approved'`)، سيقوم السيرفر برفض الطلب برسالة خطأ `403` كالتالي:
```json
{
    "status": false,
    "message": "You must verify your profile before creating a service."
}
```
**المطلوب في الموبايل:** فحص قيمة `mandatory_service_verification` من الـ Settings، وإذا كانت `true`، تأكد من إظهار واجهة التوثيق للمستخدم بدلاً من واجهة إنشاء الخدمة إذا لم يكن موثقاً.
